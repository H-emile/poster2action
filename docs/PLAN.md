# 一图成行 Poster2Action · 实施计划

> 状态：P1–P4 跑通；活海报 / 自定义块 / 发行前体检 / 本机 OCR（可选云端模型）（2026-10-17）· 目标交付日 2026-11-06

## 0. 一句话

一张静态活动海报 → 一个**每条信息都能倒查回海报原位置**、**能切换阅读方式**、**能直接加入日历/导航/分享**的活动页面。

## 1. 这份原型要验证什么

只验证三个假设，假设不成立就止损，不做功能堆砌。

| # | 假设 | 验证方式 | 失败即意味着 |
| - | - | - | - |
| H1 | 用户愿意为"可核对"多花几十秒 | 同一张海报：手工抄信息 vs 用本工具，比耗时与漏项数 | 追溯是伪需求，价值只剩"排版" |
| H2 | 追溯能真的抓出错误 | 预置 3 类陷阱（星期与日期冲突 / 价格待定 / 报名方式无链接），看系统是否在用户提交前拦住 | 追溯只是装饰，不产生信任 |
| H3 | "能直接行动"比"总结成一段话"更有用 | 点添加日历/导航，5 秒内完成闭环 | 说明该做的其实是"可复制的摘要" |

**止损判据**：如果 3 位同学在 H1 上比手工更慢，或 H2 的陷阱一个都没被提示，就停掉这个题目，不进入 10 月 25 日之后的打磨阶段。

## 2. 不做的事（明确划界）

- 不做账号体系、不做后端、不做数据库（首版本地存储 + URL 携带数据）。
- 不做海报模板编辑器（那是另一个产品）。
- 不做"自动生成整段营销文案"，页面文字只来自海报 + 用户补充。
- 不假装有 OCR：模型未接入时，界面必须**明确**显示"该信息来源：手动框选"，不允许把人工结果伪装成模型识别。

## 3. 关键取舍

### 3.1 识别路径：双通道，默认不依赖 API

| 通道 | 说明 | 何时用 |
| - | --- | --- |
| `fixture` | 10 张示例海报带**生成时就记录的真实文字坐标**，等价于"模型识别结果" | 演示、验证、对比实验 |
| `manual` | 用户在海报上拖框 → 绑定到字段，即"OCR + 人工校对" | 用户上传自己的海报；无 Key 时的兜底 |
| `vision` | 预留单一适配文件 `src/lib/extract.ts`，接视觉模型时只改这里 | 有 Key 后接入 |

这样"能不能用"不取决于有没有 API Key —— 符合计划书里"AIP 只是手段，不是产品成立的必要条件"。

### 3.2 分享：无后端方案

- 活动数据压成紧凑 JSON → base64url → 放进 URL hash（`#/v/<data>`），二维码直接编码这个链接，**扫码即可看**。
- 局限（界面上要如实说明）：上传的图片不会随链接分享；示例海报因为走静态路径所以完整。粘贴链接过长时提示改用示例海报或后续接后端。
- 附 `.json` 导出/导入作为兜底。

### 3.3 数据模型（唯一事实源）

```ts
Field   = { key, value, rect?, confidence: 'high'|'low'|'none', origin: 'poster'|'inferred'|'manual', note? }
EventDoc= { id, createdAt, posterUrl, posterW/H, fields: Field[], confirmed }
```

`derive(doc) → EventModel` 负责把 `when` 原文解析成 `startISO/endISO/allDay`，并产出 `Issue[]`。
**校验层是本项目的核心资产**，不是附件：

1. 星期与日期不符（"11月8日 周六"，实际是周日）→ error
2. 海报没写年份 → 按未来最近一次推断 → info
3. 只写"每周六"→ 只能生成单场 → info
4. 跨天（28 日 09:00 – 29 日 21:00）→ 提示确认
5. 只有场地名没有地址 → 地图可能不准 → warn
6. 价格"待定/详见群公告" → warn
7. 提到扫码报名但无链接 → warn（给出"粘贴链接"入口）
8. 任意字段 `confidence: 'low'` → 汇总提示

### 3.4 页面结构（三屏一链路）

```
入库台 Desk        校样台 Proof                  行动页 Action
┌───────────┐     ┌──────────┬──────────┐      ┌────────┬──────────┐
│ 拖入海报   │ ──▶ │ 海报(钉住) │ 校样表    │ ──▶  │ 海报缩略 │ 手机框    │
│ 或选示例   │     │ ①号高亮   │ ①-⑧ 行   │      │ 联动高亮 │ 4 种阅读  │
│ 10 张网格  │     │ 拖框标注  │ 状态/置信 │      │          │ 模式     │
└───────────┘     └──────────┴──────────┘      └────────┴──────────┘
                    存 localStorage             .ics / 地图 / QR / 链接
```

- **追溯**：点任何字段 → 海报上出现荧光笔高亮框 + 引线 + 页边圈注编号；反向也成立（点海报区域 → 定位字段）。
- **无障碍呈现**：标准 / 大字（基准 22px、行高 1.7、按钮 48px）/ 简明（只留时间·地点·行动）/ 结构化（`<dl>` 线性阅读、高对比、去装饰），四者是同一份 JSON 的四种渲染。
- **动作**：`.ics`（含 `Asia/Shanghai` VTIMEZONE、全天分支、75 字节折行）、Google 日历链接兜底、高德/OSM 搜索型地图链接（无需 Key）、二维码、复制文字。

### 3.5 设计语言

主题来自海报印刷本身：**打样台（proof sheet）**。

- 色：纸 `#E7DFCD` / 墨 `#141310` / 凸版蓝 `#2438C9` / 荧光粉 `#FF3D68` / 高亮黄 `#FFE75C` / 印绿 `#0E7A5F`
- 字：Archivo Black + Noto Sans SC 900（标题）/ Space Grotesk + Noto Sans SC（正文）/ IBM Plex Mono（数据、状态、时间）
- 记忆点（只花一处）：**荧光笔高亮 + 校对引线 + 页边圈注**。字段行号 ①-⑧ 真实对应海报上的圈注位置，编号承载"这是第几条被提取的信息"，不是装饰。
- 底线：键盘可见焦点、`prefers-reduced-motion`、手机竖屏可用。

**实现时的偏差（诚实记录）**：字体改为系统 CJK 衬线（`Songti/宋体`）+ 等宽字体（`ui-monospace`），不引外网字体，离线也能跑；色板收敛成 纸 `#E8E4D8` / 墨 `#15171B` / 青 `#0C7A8E`（出处与可信）/ 红 `#B5342A` / 琥珀 `#8A5A00`。记忆点落在「值下面的线编码可信度（实线看得清 / 虚线不太确定 / 点线图上没有）+ 框右上角编号」，编号仍真实对应海报上的位置。

## 8. 上传 + 拖框（2026-10-17 补上）

计划里 `manual` 通道（OCR + 人工校对）落地成「自己拖框标注」：

- 左栏「我的海报」→ 上传一张（或直接把图拖进页面）。图片压到长边 ≤1800、转 JPEG，存 **IndexedDB**；字段 JSON 仍存 localStorage（5MB 装不下照片）。
- 上传的文档**字段全空、不假装识别**：标题栏写「你上传的这张海报 · 没有人替你填过」；每个字段有「框选原文」。
- 点「框选原文」→ 海报上拖一个框 → 框写到该字段，可信度默认「不太确定」，note 记「这个框是你自己圈的；框里的字也是你打的，没有自动识别」；松手后光标直接进输入框。
- 框可以点回原图；可信度小标签可以点一下改成「看得清」（只对动手框过、且不是空的字段开放）。
- 刷新后原图从 IndexedDB 取回；「记住上次在看哪一张」（`p2a.current.v1`）。删掉的海报连图一起删。

验收：`.tmp/verify-upload.py` 27 条全绿、控制台 0 错误（上传→拖框→填字→改可信度→点回原图→刷新回原图与框→并存两张→删一张→414px 无溢出）。截图 `docs/shots/11-upload-drag.png`、`12-uploaded.png`、`13-mobile-upload.png`。


## 9. 「识别不出来」这件事怎么讲清楚（2026-10-17）

试用时最容易被误解的一点：上传的海报**完全不进模型**，所以进来是空的。这不是坏，但原来的界面只在脚注里提了一句，用户会以为是识别失败。改成三条明确的引导：

1. 右栏顶部一张引导卡（`.upload-guide`）：标题「这张海报我没有替你识别」，正文说清「字段是空的——不是坏了」，三步走：点「框出原文」→ 圈住那段字 → 照着打进去；按钮「从『活动名称』开始，带我一项一项圈」。
2. **领圈模式**（`guided`）：点按钮后直接进入标注态，圈完一项自动跳到下一个空的核心字段（活动名称 → 时间 → 场地 → …），一圈到底；Esc 或「取消」随时退出，退出后手动画框就只停在你圈的那一项。
3. 舞台上（`needBoxes`）再加一句：「这张没被识别过，所以图上还没有框」。

顺带修正两处措辞：按钮「框选原文」→「框出原文」（框是动作，不是选项）；低置信汇总从「有 N 项识别把握不大」→「有 N 项标记为『不太确定』」（手圈的框也算不太确定，说「识别」不准确）。

验收：`.tmp/verify-upload.py` 32 条全绿（新增引导卡文案、舞台提示、领圈起点、Esc 退出领圈四条）。截图 `docs/shots/14-guided-start.png`、`15-guided-next.png`。

**如果以后要真的自动提取**：`src/lib/extract.ts` 里 `visionAdapter: VisionAdapter | null` 是唯一的接入点，接上之后上传的文档在 `onUpload` 里先跑一次提取，把结果写成 `origin:'poster'` + 坐标 + confidence，人工只负责核对；现在这条线故意留空，因为「不假装有 OCR」是计划 §2 划的界。


## 10. 给海报装按钮（活海报）· 2026-10-17

定位变了：原来的「上传 + 拖框 → 抄成字段」，手打比圈框快，圈框是纯成本。现在圈出来的每一块都要在**观众那边**产生动作，而且**只圈不写也能发**。

### 数据
- `SpotAction = 'when'|'place'|'price'|'signup'|'zoom'`；`Hotspot{id,rect,label,text,action}`；`EventDoc.hotspots?`。
- **坐标只有一个源**：字段块用 `Field.rect`，自定义块用 `Hotspot.rect`；`collectSpots(doc)` 把它们合成一份 `Spot[]`（id 为 `f-<key>` / `h-<id>`），按 `Math.round(rect.y*20)` 分档再按 x 排，编号 1..N 即阅读顺序。
- `spotCapabilities(spot, model)` 决定抽屉里哪些动作可用：时间有起点才能加日历；有场地/地址才能导航；有报名链接才能跳转；有文字才能复制；四者皆无就是「只能放大」。

### 交互
- 观众打开的是**原图铺满**的页面，每块是虚线框（编号在框外右上）。点开 → 底部抽屉：CSS 裁切放大（`background-size: 100/w% 100/h%`、`background-position: x/(1-w)% y/(1-h)%`，四周再留 2.5% 呼吸）+ 原文 + 动作。
- 抽屉是 `role="dialog" aria-modal`，打开聚焦关闭键，Esc / 点遮罩关闭并回填焦点；按钮 44px；`prefers-reduced-motion` 关动效。
- 没写字的块照实说「这一块还没有人抄成文字——框在了，字还没写。」；没有可用动作的块说「这一块没有别的动作，留着放大看字。」
- 校样台里：`.add-spot`「＋ 圈一块图上别的东西」→ 拖框 → 起名卡片（名字 / 这一块点开能干什么 / 可空的原文），脚下列出已圈的块并可删。

### 发行前体检（`src/lib/checkup.ts`）
八类判断 + 一条兜底：`no-spot`（一个能点的都没有）、`open-errors`（还有必须处理没修）、`signup-closed`（报名已过）、`signup-deadline-after-start`（截止晚于活动结束）、`free-vs-paid`（海报写免费、别处又写票价）、`date-end-before-start`、`edited-vs-original`（手改过且与原文不一致）、`two-places`（场地里塞了两个地点）。结论只有两句：「可以发」/「N 项会出事 · M 项看一眼」。

### 分享
`Packed.n?: [rect, label, text, action首字母][]`；label 截 12 字、text 截 40 字；`VERSION` 仍是 1，旧链接照旧能解。最长链接实测 1544 字符（p08）。

## 11. 活海报的验收与边界 · 2026-10-17

验收（全绿、控制台 0 错误）：`scripts/check-hotspots.mjs` 36 条（10 张海报合计 97 个可点块、编号顺序、能力判定、体检各规则、分享往返、链接长度）；`.tmp/verify-live.py` 41 条（默认活海报、点时间块下载的 .ics 含活动名与上海时区、点场地块三条导航、只圈不写也能发、无图落地页、手机抽屉不越界、414px 不横溢）；`.tmp/verify-upload.py` 39 条；`.tmp/verify-p3.py` 26 条；`.tmp/verify.py` 12 条。

诚实边界：
1. 活海报不「理解」海报——每一块是人圈的、名字是人起的；没有模型参与，也就不会认错，但需要人动手。
2. 分享链接只带文字与坐标，**不带图**；收链接的人看不到原图时会明确告诉它、并落到文字版。
3. 抽屉里的「放大」是背景放大，不是更高清的图（原图分辨率就是上限）。
4. `.ics` 只验了文件内容，没在真机日历里导入过；二维码没被第二台手机实扫过。
5. 全部验证跑在 Edge（Playwright `channel="msedge"`），Safari / 微信内置浏览器未测。


## 12. 可选：接入视觉模型 / OCR · 2026-10-17

用户要求接入（SiliconFlow，Qwen3-VL 系列）。三条硬规矩写进了代码，不靠自觉：

1. **key 不进前端**。`vite.config.mjs` 里加了 `/api/llm` 代理：浏览器只请求 `/api/llm/v1/chat/completions`，Authorization 头由 Node 侧从 `.env.local` 的 `SILICONFLOW_API_KEY` 注入。`.env.local` 和 `.secrets/` 都在 `.gitignore` 里；`dist/` 里没有 key。
2. **模型再准也要带出处**。`src/lib/vision.ts` 的 `applyVision(doc, run)`：每个字段收 `value / quote / bbox / confidence`；没有 `quote` → 一律 `low`；没有 `bbox` → 不画框、note 写「没给出位置」；`bbox` 兼容「左上+宽高」和「左上+右下角」两种返回格式（`x+w > 1.002` 判为后者）。写进去的字段 `origin: 'poster'`、`note: '模型读的。框是它给的位置，请对照原图确认。'`，右栏字段行显示角标「模型读的」。
3. **只填空字段**。已经有内容的字段返回 `kept` 计数、不覆盖；热点（`hotspots`）按标签去重、最多 6 个。

界面：上传海报后，右栏出现「让模型先读一遍（可选）」卡片（只有 `/api/llm/health` 说配好了才显示）。错误一律翻成人话：401 说 key 没被接受、402 说额度不足、429 说太密。

### 两种模型、两条路（按模型名自动认）

| 模式 | 触发 | 模型示例 | 模型给什么 | 界面 |
| - | - | - | - | - |
| `json` | 模型名不含 `ocr` | `Qwen/Qwen3-VL-8B-Instruct` | 字段 + 原文片段 + 位置 | 直接填字段、画框、加可点块，每项标「模型读的」 |
| `ocr` | 模型名含 `ocr` | `deepseek-ai/DeepSeek-OCR`、`PaddlePaddle/PaddleOCR-VL-1.5` | 整页文字，一行一条，**没有位置** | 列出抄下来的每一行，点一行就复制；位置仍由人圈——模型只解决「打中文慢」 |

为什么 OCR 模式不硬塞进字段：OCR 模型不给坐标，硬填只会让「点回原图」这个卖点消失。所以 ocr 模式下系统**不动字段**，只把文字摊在右栏，人圈一块、粘一条，框和字两边都对得上才算数。

### 模拟模式（不花钱也能验证界面）

`.env.local` 里 `VISION_MOCK=1` 时，`/api/llm/health` 返回 `mock-ocr`（或把 `VISION_MODEL` 设成 `mock-json` / `mock-ocr` 选分支），前端用内置样例数据走完整流程，卡片上标「模拟数据」。用途：没额度 / 断网时演示或回归界面。实测两条分支都通：`mock-ocr` → 11 行文字、点一行复制成功；`mock-json` → 3 项字段 + 1 个可点块 + 3 个「模型读的」角标。截图 `docs/shots/23-ocr-lines.png`、`25-ai-filled.png`。

### 实测记录（诚实版）

- 首次调用成功：`Qwen/Qwen3-VL-8B-Instruct` 用 30.0 秒、2238 prompt tokens + 610 completion tokens，把「午夜放映 / BLADE RUNNER / 11.13 周五 22:00 / 图书馆负一层·影音厅 / 电梯直达 B1，出电梯左手边 / ¥15 人（含爆米花）/ 扫码进群报名，人满即止 / 联系人：周 18600001111」全部读对，另给 2 个可点块（「通宵连映·散场约 01:30」「限 60 人·影迷会成员优先」），每条都带 `quote` 和 `bbox`。
- 紧接着第二次调用起全部 `402 insufficient balance`（文本模型也一样）——这个 key 的余额/免费额度已经用完。页面会显示「账户额度不足（402）…手动圈框那条路完全不受影响」。所以现在的验收是：**链路通、错误处理通、无额度时的降级通**；有额度时的字段质量只有上面那一次样本。

- 因此 4 套浏览器验收（12 / 26 / 39 / 41）依然全绿——它们跑的是默认的无模型路径；视觉两条分支用模拟模式验过界面与流程。


## 13. 本机 OCR：不花钱、离线、不要 key · 2026-10-17

起因：云端 API 全部 402（详见 §12 与下面「为什么收费」）。结论是「识别」这件事不该绑在一张要充值的卡上，于是接了 **tesseract.js（wasm）在本机跑**。

### 实现
- `src/lib/localOcr.ts`：`runLocalOcr(dataUrl, onProgress)` → `{lines, ms}`。
  - **预处理**（canvas，无网络）：放大到长边约 1800；一遍只灰度放大，一遍额外拉对比 + 深底反相，两遍都跑。
  - **合并**：两遍的「行」按置信度去重（字符二元组 Dice ≥0.62 视为同一行），丢掉置信度 <55 且中文 <4 字的噪声，最后**按纵坐标排序**（OCR 自己的顺序常常是乱的）。
  - **汉字空格**：`tidy()` 去掉汉字之间的空格（「图 书 馆」→「图书馆」），英文/数字间保留。
- 资源放 `public/`，随站点发布、不走 CDN：`tesseract/worker.min.js`、`tesseract/tesseract-core-simd-lstm.wasm.js`、`tessdata/chi_sim.traineddata.gz`（19.2MB）、`tessdata/eng.traineddata.gz`（10.4MB）。语言包从 `https://tessdata.projectnaptha.com/4.0.0/` 取（Tesseract 的 Apache-2.0 训练数据）。
- 界面：右栏「让机器先抄一遍（可选）」里有两个按钮——**本机 OCR（免费 · 离线）** 常驻；云端模型只在 `/api/llm/health` 说配好了才出现。抄完列出每一行，点一行复制，圈住哪块粘到哪一项；**位置一律人圈**。

### 实测（午夜放映海报 1200×1600，同一张图）
| 轮次 | 结果 | 耗时 |
| - | - | - |
| 初版（单遍、无预处理） | 9 行；`11.13 FH 22:00`、`图 书 馆 负 一 层 。 影 音 厅` | 6.1 s |
| 反相+拉对比（单遍） | 9 行；`周五` 读对了，但中文正文被反相毁掉（`EE 81:30`） | 5.6 s |
| 两遍 + 按置信度合并 + 噪声过滤 | **12 行**；`11.13 周五 22:00`、`图书馆负一层。影音厅`、`电梯宣达「B1;｜出电梯左手边`（宣→直错）、`¥15 / 人（含爆米花）` | **2.5–10.6 s** |

诚实结论：**艺术字标题（「午夜放映」）和细小的副信息经常读不出或读错**（`EE 81:30`），英文全大写行反而准。所以它的定位是「省掉手打中文」，不是「替人读懂海报」；框和字仍然两边对得上才算数。控制台会出现 tesseract 自己的 `Parameter not found` 警告（v7 与内核参数版本差），不影响结果。

### 与云端模型的关系
两条路并存、互不影响：`.env.local` 里 `VISION_MODEL` / `SILICONFLOW_API_KEY` 一填，云端按钮就出现；不填，本地 OCR 照样能用。比赛演示默认走本地（断网也不怕）。
